# 产品视频精剪与命名（TikTok 素材预处理）

## 1. 输入与默认设置

- 输入为用户提供的本地文件夹绝对路径，每次使用当前路径，不将示例路径作为固定输入。
- 只处理输入文件夹直属视频，不递归处理子文件夹。
- 成品目录建在输入目录**同级**，命名为"输入文件夹名称_剪辑后"；已存在则沿用，不重复嵌套。
- 每条视频独立处理，只修剪片头、片尾，不删除中间内容，不拼接。
- 保留原音频，不添加字幕、音乐、转场、滤镜或其他效果。
- 默认处理：修剪片头、片尾；用户未提及其他处理时直接执行修剪，不另行询问。
- 默认输出：保留源容器与编码族（原格式）；默认仅保留标准 AAC 音轨，丢弃苹果空间音频 APAC 与 mebx 元数据流（剪映兼容）。
- 默认**移动**输入目录中的非视频文件（参考图、脚本、文档等）到成品目录，完成后输入目录只剩原始未处理视频；用户明确要求保留原位时不移动。
- 用户明确指定的输出约束（如保留全部音轨、转 MP4、带序号、不移动文件等）优先于默认策略；开工前先确认并记录。

## 2. 工具与执行前检查

优先使用 ffprobe 读取参数、FFmpeg 裁剪和编码、Python 批量命名与整理文件，使用可用的图像查看工具判断内容。

1. 确认输入目录可访问、成品目录可写，检查 FFmpeg、ffprobe 是否可用。
2. 建立源文件清单，通过视频流识别素材，不仅依赖扩展名。
3. 排除成品目录、工作目录、临时文件和失败输出。
4. 检查磁盘空间，考虑源文件与成品同时存在。
5. 读取已有任务记录，确定处理、恢复或跳过的项目。
6. 跑一遍剪映兼容性预检（见第 4 节），提前识别 APAC/mebx 问题。

路径包含中文、空格和特殊字符时，使用参数数组调用程序，禁止直接拼接 shell 命令。长任务定期报告进度，不因短时无输出认定失败。

缺少工具或无法访问路径时，说明具体障碍，不擅自更改系统配置，不声称已经完成无法执行的操作。

## 3. 内容观察与剪辑决策

先观察，再裁剪。FFmpeg 负责执行，不负责理解语义。

### 观察命令模板（直接复用）

全片低帧率带时间戳预览拼图（一张图看完全片节奏）：
```
ffmpeg -i input.mp4 -vf "fps=1/2,drawtext=text='%{pts\:hms}':x=10:y=10:fontsize=28:fontcolor=yellow:box=1:boxcolor=black@0.6,scale=480:-1,tile=5x4" -frames:v 1 preview_full.jpg
```

片头/片尾高密度帧（各取前 3 秒和后 3 秒，每 0.75 秒一帧拼成一张图）：
```
ffmpeg -i input.mp4 -vf "select='lt(t,3)+gt(t\,duration-3)',drawtext=text='%{pts\:hms}':x=10:y=10:fontsize=28:fontcolor=yellow:box=1:boxcolor=black@0.6,scale=480:-1,tile=4x2" -frames:v 1 preview_edges.jpg
```

静音检测（辅助判断无效片段，不单独作为删除依据）：
```
ffmpeg -i input.mp4 -af silencedetect=noise=-35dB:d=1 -f null -
```

### 观察原则

- 优先查看完整视频；无法直接播放时，用上述预览拼图快速浏览。
- 候选起止点附近增加采样密度，必要时查看短片段以确认动作边界。
- 涉及说话内容时同步检查音频波形。
- 稀疏截图、静音、黑帧和运动检测只能作为线索，不得单独作为删除依据。
- 无法可靠观察时不猜测剪辑点，保留原片并标记待复核；命名不确定字段使用"待确认"。

仅删除片头、片尾明确无效的空画面、过长准备动作、收拾动作或无效等待。保留完整产品展示、操作过程、结果、必要静态展示与停顿、完整动作和说话内容。不将静音、静止或慢动作本身认定为无效。

全片没有明确有效内容时，不输出空视频，保留原片并标记待复核。

设有效内容开始时间为 S、结束时间为 E、源片时长为 D：
- 保留起点 = max(0, S - 0.5秒)。
- 保留终点 = min(D, E + 0.5秒)。
- 边界对齐可用视频帧，优先向外保留，避免截断动作。
- 素材不足 0.5 秒时保留已有部分，不补帧或延长。
- 必须满足 0 ≤ 起点 < 终点 ≤ D。

仅一端多余时只剪该端；无明显冗余时不剪；存疑时宁可少剪。

## 4. 输出策略

按顺序选择：
1. 无需剪辑且可直接使用：复制，不重复编码，不强制改变原码率。
2. 无需剪辑但容器不适合剪映：视频流 copy + 音频按需处理（见下）。
3. 需要剪辑：精确裁剪并重新编码，不使用关键帧粗切作为最终成品。

### 剪映兼容性预检

批量处理前先对每条素材跑一次流探测：
```
ffprobe -v error -show_entries stream=codec_type,codec_name,channels -of csv=p=0 input.mp4
```
- 出现 `apple_apac` 或 `mebx` → 需要去 APAC/mebx 流程。
- 只有一条 AAC 立体声轨 → 可直接 copy，无需重编码音频。
- 无音轨 → 不新增音轨。

### 音轨映射规则（先探测再 map）

不要硬编码 `-map 0:a:0`。先跑上面的 ffprobe，找到 codec_name=aac 的那条音轨 index，再 map。
- 默认只保留 AAC 音轨，丢弃 APAC、mebx 及其他专有数据流（这是剪映兼容的必须操作，不算"静默丢弃"）。
- 除 APAC/mebx 外的额外音轨（如其他摄像头源、多语言音轨）不得静默丢弃，无法完整保留时记录异常。
- 源 AAC 参数已达标（≥192k、48kHz）时用 `-c:a copy`，不重编码；否则转 AAC 192k。

### 默认输出原格式

- 保留源容器与编码族：MOV/MP4 源输出同容器；HEVC 源保留 HEVC，H.264 源保留 H.264。
- 保持原分辨率、显示比例、方向及实际帧率，29.97、59.94 等不得取整。
- **禁止使用 `-r` 参数；filter_complex 中禁止插入 `fps=` 滤镜**（除非用户要求变速）。
- 不拉伸、裁切、变速、插帧或无故丢帧。
- 默认不保留字幕轨、封面缩略图轨和章节信息；用户需要时单独映射。
- 需 SDR 转码时参考码率：4K H.264 约 18 Mbps（15–20），1080p 约 8–12 Mbps，720p 约 4–6 Mbps。

### HDR 与 10 位素材

- 默认保留原容器（如 iPhone MOV），不强制转 MP4；容器、编码、位深、色彩参数保持一致。
- 输入加 `-noautorotate` 保持像素方向与显示矩阵旋转元数据一致。
- 输出命令（修剪 + 原格式 + 单 AAC）：
  `-map 0:v:0 -map 音频流index -c:v libx265 -preset fast -crf 18 -pix_fmt yuv420p10le -tag:v hvc1 -color_primaries bt2020 -color_trc arib-std-b67 -colorspace bt2020nc -c:a aac -b:a 192k -ar 48000 -ac 2`
- HLG 传递无需 master-display 元数据；PQ 素材另查参数。
- Dolby Vision Profile 8 重编码后 RPU 会丢失，但 HLG 基础层保持；在记录中注明。
- 编码后用 ffprobe 核对：codec_name=hevc、profile=Main 10、pix_fmt=yuv420p10le、色彩标签与源一致、rotation 与源一致。
- 色彩参数不确定时先小段试编码（如 2 秒）核对再跑全片。

### H.264 素材（8 位）

- 默认保留 H.264 与 8-bit 位深，不升 10-bit、不转 HEVC。
- 输出命令：`-map 0:v:0 -map 音频流index -c:v libx264 -preset veryfast -crf 18 -pix_fmt yuv420p -color_primaries bt2020 -color_trc arib-std-b67 -colorspace bt2020nc -tag:v avc1 -c:a aac -b:a 192k -ar 48000 -ac 2`
- 注意：H.264 封装 HLG/bt2020 属于 iPhone 非常规输出，部分平台显示为 SDR；交付 TikTok 前在目标平台验证色彩。

### 硬件编码（按需启用）

- 先探测本机是否有 NVIDIA 独显：`ffmpeg -hide_banner -encoders | findstr hevc_nvenc`。
- 有 hevc_nvenc 且驱动 ≥ 610 可试 `-c:v hevc_nvenc -preset p5 -cq 18`，小段验证 HDR 参数通过才全片用。
- 验证失败回落 libx265，不无限重试。
- 无 N 卡直接用 libx265，不折腾 QSV/AMF/videotoolbox（Windows 台式机场景下默认软件编码即可）。

### 高效处理流程

- 单次观察：用上面的预览拼图 + 静音检测命令，一次跑完，减少工具往返。
- 单次输出：从源视频直接一次编码输出（视频 + 单 AAC，不映射数据流），避免多轮重封装。
- 全保留且只需去 APAC/mebx 时：视频流 copy + 音频按需 copy/重编码，秒级完成零画质损失。
- 批量执行：把每条的决定写成计划表（源文件名、成品名、S、E、编码族、是否重编码），按表批量执行，逐条独立。
- 每条输出到工作目录 `.partial` 文件 → ffprobe 验证（流数=1视频+1音频、编码/位深/色彩标签、时长在计划范围）→ 通过才改正式名 → 追加写 CSV 行；失败单条记录后继续。

## 5. 成品命名

公式：`片段内容_景别_运镜_氛围_日期简写.mp4`

示例：
- `外观展示_近景_固定镜头_日常_261019.mp4`
- `拧紧螺丝_特写_推进_日常_261019.mp4`
- `节日礼盒开箱_全景_环绕_圣诞_261019.mp4`

### 片段内容
- 根据成品实际保留内容命名，使用外观展示、拧紧螺丝、更换批头、地面行驶等简洁词组，相同内容统一用词。
- 多动作选主要动作；两个同等重要用"动作A与动作B"；超过两个且无主次用"多步骤操作"。
- 无法判断填"内容待确认"。

### 景别
统一使用：特写、近景、中景、全景、多景别、景别待确认。按主要有效内容判断，无主次时使用多景别。

### 运镜
统一使用：固定镜头、推进、拉远、左横移、右横移、上升、下降、左摇、右摇、上摇、下摇、环绕、跟拍、变焦推近、变焦拉远、复合运镜、运镜待确认。
- 判断摄像机运动，不把主体移动或旋转误判为运镜。
- 横移为摄像机位置移动；摇镜为摄像机转动拍摄方向。
- 轻微手持抖动仍归为固定镜头，以主要运镜为准。
- 同时两种明确运镜用"推进加环绕"等，最多组合两种；更复杂无主次用复合运镜。
- 无法区分推进和变焦等情况填"运镜待确认"。

### 氛围
- 默认"日常"。
- 明显为节日场景填具体节日名，如：圣诞、新年、情人节、春节、母亲节、万圣节等。
- 无法判断填"氛围待确认"。

### 日期简写
- 格式：两位年份 + 两位月份 + 两位日，如 261019（2026年10月19日）。
- 默认用素材拍摄日期（从源文件修改时间或媒体元数据取），取不到时用处理当天日期。

### 文件名规范
- 简洁中文，不添加精彩、高级、视频素材等无效词。
- 下划线仅作字段分隔符；去除 Windows 非法字符：`\ / : * ? " < > |`。
- 去除末尾空格、句点，避开系统保留名称。
- 过长时缩短描述字段，保留完整字段结构。
- 扩展名与实际容器一致。
- 重名先核对记录，不覆盖；确需另存，在扩展名前追加"_v2"等标记。
- 包含待确认的项目全部列入复核清单。

## 6. 源文件保护与恢复

- 源视频保留原位，不覆盖、不删除、不移动、不改名。
- 成品目录内设独立工作子目录存放临时文件和任务状态，临时输出保留正确扩展名，如"编号.partial.mp4"。
- 验证通过才在同一磁盘内改为正式成品名，正式文件已存在时禁止替换。
- 任务记录包含源文件名、大小、修改时间、成品名、剪辑起止点、命名依据、处理状态、复核标记和异常原因。
- 每条处理后立即保存记录，临时记录写完再原子替换，防止中断损坏。

重复执行：
- 仅跳过源文件未变化、成品存在且验证通过的项目。
- 使用文件名、大小、高精度修改时间判断变化，存疑比较内容哈希。
- 成品丢失、损坏或源文件变化时重做，旧成品不覆盖，新成品另存版本并更新记录。

## 7. 验证与异常处理

每条成品检查：
1. 存在且非空，ffprobe 可读取。
2. 完整音视频解码无错误。
3. 时长符合计划范围，偏差超过正常帧误差时复核。
4. 分辨率、方向、比例、帧率或时间戳符合策略；HDR 素材核对色彩参数及旋转元数据与源一致。
5. 默认输出流数应为 1 视频 + 1 音频（去 APAC/mebx 的验收标准），多出数据流或 APAC 视为失败。
6. 实际查看首尾，动作完整，无新增异常黑帧。
7. 检查有声素材音画同步；不能实际检查时注明。

旋转元数据核对：
```
ffprobe -v error -select_streams v:0 -show_frames -read_intervals "%+#1" -show_entries frame_side_data_list=side_data_type,rotation
```

不得仅凭 FFmpeg 成功返回认定通过。

- 单条失败不阻止其他视频，可恢复错误最多自动重试一次，仍失败记录后继续。
- 空间不足、目录失去权限等全局问题暂停批处理，保存进度并说明。
- 不自动删除成品或源视频释放空间，仅清理本次任务明确创建的临时文件。
- 无法验证的项目标记"验证未完成"，不计为验证通过。

## 8. 文件整理与清单

- 成品统一放入成品目录；无需剪辑视频也复制并统一命名。
- 全部视频成功输出且验证通过后，**默认将输入目录直属其他普通非视频文件移动到成品目录**，与剪好的视频归档在一起。
- 用户明确要求不移动文件时跳过此步骤；移动前先复制并核验内容一致，再删除源位置文件。
- 已有子目录、符号链接、任务记录、锁文件、临时文件不参与移动。
- 无法读取的疑似视频不得当普通非视频移动。
- 同名追加序号，禁止覆盖；记录移动前后路径，避免恢复时重复移动。

成品目录保存"处理清单.csv"，UTF-8 带 BOM。

字段：源文件名、成品文件名、源文件大小、源文件修改时间、处理方式、处理状态、是否剪辑、保留起点、保留终点、原时长、成品时长、分辨率、帧率、验证结果、复核备注。

时间格式"时:分:秒.毫秒"，起止点均相对于源视频。

## 9. 完成报告

简要给出：
- 扫描总数，精剪、直接复制、仅封装转换、其他转码数量；
- 失败、跳过、待复核数量；
- **每条成品的最终时长**（方便挑选适合 6 秒/15 秒/30 秒的素材）；
- 成品目录和清单路径；
- 未完成事项和具体原因。

待复核数量可能与已输出数量重叠，应说明。无法访问、查看、处理或验证的内容如实报告，不编造结果。
